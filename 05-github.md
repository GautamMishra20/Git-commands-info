# GitHub: The Home of Your Git Repositories

Git helps you manage versions of your project on your computer. GitHub extends that capability by providing an online platform where repositories can be stored, shared, and maintained collaboratively.

Think of Git as the tool that records changes, while GitHub is the platform that hosts and distributes those changes.

---

# Understanding the Difference

| Aspect            | Git                    | GitHub                                 |
| ----------------- | ---------------------- | -------------------------------------- |
| Type              | Version Control System | Repository Hosting Platform            |
| Location          | Runs on your computer  | Accessible through a web browser       |
| Internet Required | No                     | Yes, for synchronization               |
| Purpose           | Track project history  | Store and share repositories           |
| Usage             | Individual development | Team collaboration and project hosting |

---

# Why Developers Use GitHub

## Secure Cloud Storage

Projects stored on GitHub are available online, providing an additional layer of backup beyond the local machine.

---

## Collaborative Development

Multiple contributors can work on the same project while keeping changes organized through branches and pull requests.

---

## Project Distribution

Repositories can be shared publicly, allowing others to view, clone, and contribute to projects.

---

## Professional Visibility

GitHub profiles showcase repositories, contributions, and development experience, making them valuable for internships, jobs, and academic opportunities.

---

## Open-Source Participation

Many widely used software projects are hosted on GitHub, enabling developers to contribute improvements, fixes, and new features.

---

# How GitHub Connects Developers

A typical workflow involves multiple local repositories connected to a single remote repository hosted on GitHub.

```text id="6o7azk"
        Developer 1
      (Local Repository)
              │
              │ Push Changes
              ▼
      GitHub Repository
      (Remote Repository)
              ▲
              │ Pull Changes
              │
        Developer 2
      (Local Repository)
```

GitHub acts as a central location where all project updates are synchronized.

---

# Major Components of GitHub

## Repository

A repository contains everything related to a project:

- Source code
- Commit history
- Branches
- Documentation
- Project configuration files

Every GitHub project is stored inside a repository.

---

## Issues

Issues help organize development tasks.

They are commonly used for:

- Bug reports
- Feature requests
- Improvement suggestions
- Project planning

---

## Pull Requests

A Pull Request is used to propose changes before they are added to the main codebase.

Typical workflow:

```text id="7qk1it"
Create Branch
      ↓
Make Changes
      ↓
Push Branch
      ↓
Open Pull Request
      ↓
Review Changes
      ↓
Merge
```

---

## GitHub Actions

GitHub Actions allow automated workflows directly within a repository.

Examples include:

- Running tests automatically
- Building applications
- Deploying projects
- Executing scheduled tasks

---

## GitHub Pages

GitHub Pages enables repositories to host static websites directly from GitHub.

Common examples:

- Personal portfolios
- Project documentation
- Landing pages
- Technical blogs

---

# Local Repository vs Remote Repository

### Local Repository

Stored on your computer.

Used for:

- Writing code
- Testing features
- Creating commits

### Remote Repository

Stored on GitHub.

Used for:

- Sharing code
- Collaboration
- Backup
- Project management
